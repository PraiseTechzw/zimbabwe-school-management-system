# Architecture Decision Records (ADRs)

An ADR records a decision that is difficult to reverse, affects multiple modules, or changes how contributors work. Small, local choices belong in a pull request description, not in an ADR. Do not create ADRs to fill the folder.

## Format

Use the existing numbered files as examples:

- Title (number + short name)
- Status: Proposed | Accepted | Superseded by ADR-XXXX
- Context (problem and constraints, with evidence where available)
- Decision (what was chosen)
- Alternatives considered (with reasons for rejection)
- Consequences (positive and negative)
- Verification / review trigger (when to revisit)

Numbering is sequential and never reused. A superseding ADR links back to the original.
